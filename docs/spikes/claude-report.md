- "codex resume <id> attaches a TUI to the session while the headless run is still going" — `codex resume` "continues a previous interactive session… reconnects to a saved session, not a currently running one"; it opens its own TUI over the saved rollout and does not mirror the live `codex exec` stream. Binary has "is already running with a different rollout path" guards. — https://learn.chatgpt.com/docs/developer-commands?surface=cli ; `strings /opt/homebrew/Caskroom/codex/0.163.0/bin/codex`
- "Working files live in the main checkout; the lead writes state.json with Write/Edit" while the lead sits in a Claude-created worktree — worktree isolation "blocks an Edit, Write, or NotebookEdit that targets a path in the main checkout" and Bash commands whose cwd resolves there. Every state.json/handoff/gotcha write from inside the worktree is refused. — https://code.claude.com/docs/en/worktrees#how-claude-code-enforces-isolation
- "PreCompact hook blocks it once and tells the lead to write the handoff first" — blocking works (exit 2 / `decision: "block"`), but the message is user-facing only: "For a manual /compact, the stderr message is shown to the user"; PreCompact has no `additionalContext` (ClassicResultFields lacks it), and `systemMessage` is discarded. The model never sees "write the handoff". Blocking an auto-compact that fires on a context-limit error makes "the current request fail". — https://code.claude.com/docs/en/hooks#precompact ; claude-code.d.ts:1060-1076
